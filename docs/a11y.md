# Barrierefreiheit – Quellenpanel

Maßstab: WCAG 2.1 AA, dazu Zielgröße nach WCAG 2.2 AA (2.5.8). Stand: Version 0.6.0 (Etappe 6).

## Automatischer Test

```bash
# Server lokal starten (siehe README), dann:
node frontend/scripts/a11y-audit.mjs http://127.0.0.1:8080 --team-pw <team-passwort>
# mit einer anderen Markenfarbe prüfen (ersetzt branding aus dem Profil):
node frontend/scripts/a11y-audit.mjs http://127.0.0.1:8080 --primary '#7fb2e5'
```

Das Skript prüft mit axe-core (Regeln `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`):
Kacheln, Liste und Statistik (Basis), Kacheln und Steckbrief (Details), Kacheln und Korrekturen
(Audit) sowie die Kacheln bei 375px Breite. Es endet mit Fehlercode, wenn Verstöße der Stufe
`serious` oder `critical` bleiben.

Ergebnis 0.6.0: keine Verstöße, mit dem WLO-Branding und mit der hellen Testfarbe `#7fb2e5`.

## Von Hand geprüft

- **Tastatur:** Die Tab-Reihenfolge folgt der Anzeige (Ansicht, Stufe, Sprache, Suche, Filter,
  Kacheln). Jede Kachel ist ein Button. Der Steckbrief hält den Fokus im Dialog, Esc schließt ihn,
  danach steht der Fokus wieder auf der Kachel.
- **Fokus:** Er ist überall sichtbar, auf Kacheln als 2px-Rahmen in `--focusColor` um den Titel.
- **Markenfarbe:** Ist die Primärfarbe des Profils zu hell für weiße Schrift (unter 4,5:1),
  stellt `branding.ts` dunkle Schrift auf Primärflächen und dunklere Text-, Tönungs- und
  Fokusfarben ein.
- **Schmale Fenster:** Unter 900px rückt die Bedienleiste in eine eigene Zeile, unter 700px zeigen
  die Schalter nur Icons. Der Name bleibt für Screenreader erhalten.

## Bekannte Grenzen

- Die Vorschaubilder kommen von den Quellen selbst und sind dekorativ (`alt=""`). Name und Anzahl
  der Inhalte stehen als Text auf der Kachel.
- Die Tooltips der Qualitäts- und Bindungs-Badges erscheinen nur bei Maus-Hover. Dieselben Angaben
  stehen im Steckbrief als Text.
